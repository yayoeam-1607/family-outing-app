# 今日どこ行く？

家族で週末のおでかけ候補を探す、スマホ対応のWebアプリです。
HTML・CSS・JavaScriptで作り、開発サーバーとビルドにViteを使っています。データベースやAPIキーは不要です。

## はじめかた

Node.js 22.12以上（この環境は24）で、リポジトリ内から実行します。

```sh
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

通常のPCでは `npm ci` だけでもインストールできます。開発サーバーが表示するアドレスをブラウザで開いてください。

```sh
npm test       # 検索・保存・移行・実在カタログのテスト
npm run build  # 公開用ファイルをdist/へ生成
npm run preview # ビルドしたアプリを確認
```

## ファイルと改良方法

- `index.html`：画面の構成と条件の選択肢
- `style.css`：色、レイアウト、スマホ対応
- `catalog.js`：公式施設案内で実在確認済みの100施設。固定IDを使用します。
- `spots.js`：旧架空サンプルと条件検索ロジック。旧データ互換のためサンプルを保管しています。
- `catalog-migration.js`：旧施設の記録を保管して実在カタログへ移行します。
- `docs/catalogue-sources.md` / `docs/catalogue-evidence.json`：100施設ごとの確認日、公式URL、確認内容、推定条件。
- `app.js`：検索ボタンの処理と結果カードの表示
- `tests/search.test.js`：検索条件の組み合わせのテスト

## 検索のルール

複数の条件をすべて満たすスポットを表示します。初期表示は実在100施設（ユーザーが追加・削除した件数を反映）で、「候補を探す」を押すと選択中の条件で検索します。

- 雨：屋内のみ。晴れ・どちらでも：屋内と屋外の両方。
- 移動時間：車／電車ごとの片道所要時間が、選んだ上限以内。
- 予算：大人2人＋小学生2人の通常入館・入園中心の目安が上限以内。無料は0円のみ。食事・交通・駐車場・BBQは原則別。
- 滞在時間：そのスポットが対応する時間と一致。`stays` の `2` は2時間、`4` は半日、`8` は1日。
- 子ども向け度：編集上の5段階の目安です。公式評価や家族の訪問評価ではありません。

2026年10月11日に公式施設案内で実在を確認した100施設を初期登録しています。公式情報の確認記録は `docs/catalogue-sources.md` にあります。
移動時間・滞在時間・子ども向け度は計画用の推定です。経路API・実測・天気予報とは連携していません。
キッザニア東京、夢の島熱帯植物館、木もれ陽の森は施設の実在を確認済みですが、最新の金額は未確定で、カードに仮予算と要確認を記載しています。
テント・BBQの許可が確認できない施設は `null`（未確認）とし、利用可／不可の両方の検索から除外します。条件付きで利用可の施設は予約・区画・持込の制限を説明に記載します。屋内施設の不可は対象外です。

## おでかけ管理機能

スポットの追加・編集・削除、お気に入り、訪問日・評価・感想・再訪意向を保存できます。
画面下のナビゲーションで探す／追加／行った場所／お気に入りを切り替えます。
トップの一覧には「また行きたい」「よく行く」「まだ行ってない」もあります。
「また行きたい」は訪問日が最も新しい記録の意向を使います（同じ日なら後に登録した記録）。
「よく行く」は訪問回数の降順です。誤った訪問記録は「行った場所」で削除して登録し直せます。
スポットを削除すると、その場所のお気に入りと訪問記録も削除されます。

データはブラウザのlocalStorage（`family-outing-data-v1`）に保存します。ログイン・サーバー保存・自動同期はありません。
同じURL・ブラウザでは再起動後も残りますが、ブラウザデータの削除やプライベートモードに注意してください。
「データを書き出す」でJSONを保存し、別の端末で「データを読み込む」と復元できます。
読み込みは全データの置き換えです。確認後に実行し、事前に現在のデータを書き出してください。
不正なJSONや非対応形式は保存前に検証して拒否します。記録を含むバックアップは共有先に注意してください。

`store.js` が保存形式の検証・移行呼び出し・訪問集計・候補並べ替え、`spots.js` がカテゴリ・旧サンプル・条件検索を担当します。
旧架空サンプルは通常候補から除き、`archivedSpots` に保管します。旧施設のお気に入りと訪問履歴の参照は維持し、実在施設へ付け替えません。
localStorageのキーは変えず、移行前のJSONは `family-outing-data-v1-before-v2` に一度だけ退避します。
ユーザー登録施設、実在カタログの編集内容、削除済み固定IDを維持し、再読み込みや改訂で復活・上書きしません。
未確認のテント・BBQは編集画面でも保持できます。
GitHub Pagesではmainのルートを公開する方法、またはViteで生成したdistを公開する方法の両方で、相対パスが使えます。

## 瑞江駅基準の家族向けおすすめ

登録フォームの移動時間は東京都江戸川区の瑞江駅からの片道目安として入力します。
住所・エリア、雨の日向き、公式サイトURL、メモも登録・編集できます。経路APIや現在の天気の自動取得は行いません。
旧データの所要時間は勝手に変更しないため、必要に応じて瑞江駅基準に編集してください。サンプルの時間は架空です。

おすすめは条件検索を維持した上で、ショッピングモール・大型公園・キャンプ・BBQ・テントOKを少し優先し、次にその他の屋外スポットを表示します。
「行った場所」は訪問日、家族評価、訪問回数の降順に切り替えられます。
旧保存データと旧JSONはそのまま読み込めます。新項目には空欄・屋内かどうかに応じた既定値を設定し、再訪意向「普通」は「どちらでも」に移行します。
