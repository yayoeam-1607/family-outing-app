# 今日どこ行く？

瑞江駅から家族のおでかけ先を探し、行った日と思い出を残し、年ごとに振り返るスマホ対応Webアプリです。白・セージグリーン・サンドを基調にした、落ち着いた画面です。HTML / CSS / JavaScriptとViteで動き、データベースやAPIキーは不要です。

## 起動・検証・公開

Node.js 22.12以上で実行してください。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
node scripts/catalogue-summary.mjs --write
```

ビルド結果は `dist/` です。Viteの `base: './'` と相対パスを維持しており、GitHub Pagesのサブパスで動作します。写真の保存機能はありません。

## 350件の候補と情報の扱い

固定ID付き350件。既存250件のIDを維持し、提供された100件を50件ずつ2バッチで追加しました。同一施設をカテゴリごとに重複登録せず、複数の中カテゴリ・タグを持たせます。牧場と別予約のキャンプ場、海浜公園と環境学習館など、独立した施設・サービスは従来のIDを維持します。

**350件登録時は依頼に従いWeb検索を行いませんでした。その後のrevision 7では公式情報で107施設を補完しました。** 既存250件の前回確認記録は `docs/catalogue-evidence.json` にあります。追加100件は当初提供された名称・施設種別だけを使用しました。今回46施設について確認できた情報を補完し、未確認項目は引き続き不明です。情報を創作せず、null / unknown / 空配列 / 空文字で表します。未確認を「不可」「無料」に変換しません。旧資料に明記された駐車場・デイキャンプ・サウナの情報だけを再利用し、根拠を `docs/v3-reused-facts.json` に保存しました。浴場の年齢制限からサウナの年齢制限を推定しません。

今回の確認件数・表示・データ保護の詳細は [施設情報の改善](docs/facility-information.md)、最新の情報充足状況は `docs/information-summary.json` を参照してください。

350件登録時の内訳・都県別・移動時間別・カテゴリ別・キャンプ・BBQ・釣りの件数は `docs/catalogue-summary.json` にあります。未確認の都県・時間も独立集計します。旧版にあった3件の仮予算は新しい予算検索に使用しません。

## 10大カテゴリと階層検索

ショッピング / 公園・アウトドア / テーマパーク・レジャー / 動物・水族館 / 屋内遊び / 学び・体験 / スポーツ・アクティビティ / 温泉・リラックス / 観光・街歩き / 自然・収穫体験。

「今日は何したい？」の自由検索、目的チップ、大カテゴリ → 中カテゴリ → 詳細タグで探せます。旧「観光スポット」はUIから廃止し、公園・植物・名所・乗り物観光などへ分類しました。旧 `category` はバックアップ互換用にだけ保持し、表示・新検索には `mainCategory` を使用します。

「さらに絞り込む」で車 / 電車、片道0〜30 / 30〜60 / 60〜90 / 90〜120 / 120〜180分、予算の下限〜上限、駐車場、天候、滞在、季節、地域、未訪問、有名スポットを指定できます。時間帯は両端を含むため、30分などの境界は隣接する帯の両方に一致します。結果数と選択条件は常時表示し、個別解除・すべてクリアに対応します。有名スポット優先は条件に一致する候補を維持して並び替えます。

異なるグループはAND、同じ中カテゴリ・タグ・季節内はOR。キャンプ・釣り・サウナの専用特徴はすべて満たすANDです。料金は家族4人分のtypicalを優先し、typicalがなければmin/maxとの範囲重なりで判定。無料は0円、不明料金は予算指定時に除外します。駐車場・移動時間・設備も不明ならその条件に一致しません。通年施設は各季節に一致します。季節は依頼にあるタグとの関連によるおすすめで、営業期間を断定するものではありません。自由検索は施設名・説明・カテゴリ名・中カテゴリ・タグ・設定季節に関連するタグを対象にします。

## お気に入りと思い出

下部ナビは「探す」「お気に入り」「思い出」「追加」の4つ。カードから詳細を開き、「行った！」で日付・★1〜5・思い出メモ・再訪意向を何度でも記録できます。初期日付は日本時間の今日。お気に入りと「また行きたい」は別に保存します。

思い出は記録のある年だけ切り替え、月別・訪問日降順のタイムラインを表示します。

- おでかけ回数＝visit件数、行った場所数＝年内のユニークspotId数。
- 一番行った場所・よく行ったカテゴリは訪問件数で集計。同数はID順。
- ★5の場所数は、その年に★5を一度でも付けたユニーク施設数。
- また行きたい場所数は、選択した年の施設ごとの最新記録で判定。同日は後に登録した記録が優先。
- 初めて行った場所数は、全履歴で最も早い訪問が選択した年にある施設数。

通常操作は「候補から非表示」。固定・ユーザー追加とも施設を `archivedSpots` に保管し、お気に入りと訪問記録を残します。データ管理や思い出から詳細を開いて復元できます。思い出を含む完全削除は、非表示施設の専用操作と2段階確認が必要です。旧架空サンプルの履歴も保管し、実在施設へ付け替えません。

## 保存形式 version 3・移行とバックアップ

localStorageキーは **`family-outing-data-v1` のまま**。version 1 / 2を検証してversion 3へ移行し、移行前のJSONを初回のみ **`family-outing-data-v1-before-v3`** にそのまま保存します。既存のbefore-v2 / before-v3を上書きしません。バックアップ保存に失敗した場合は元データを更新せず、通常保存を止めて保護します。

ユーザーの追加・編集・お気に入り・訪問日・評価・メモ・再訪意向・非表示IDを維持します。visitCountは履歴から計算します。`removedBuiltinIds` と保管データを尊重し、更新やJSON読込で非表示施設を再表示しません。旧版の完全削除で既に失われた訪問記録は復元できません。

新項目は大カテゴリ、中カテゴリ、タグ、季節、天候、車・公共交通の時間、家族4人料金、駐車場、滞在、キャンプ、釣り、サウナ。`cleanSpot` / `validateState` が全項目を検証して保存・JSON往復します。写真など未知のプロパティは保存しません。追加・編集は基本 → カテゴリ → 必要な詳細の3段階で、表示していない専用項目も保持します。

「データ管理」からJSONを書き出し・読み込みできます。読み込みは現在の状態を置き換えるため、事前に書き出してください。version 1 / 2 / 3を受け付け、不正な日付・ID重複・参照不整合・不正URL・負の料金等は拒否し、元データを上書きしません。端末間の自動同期はありません。

- `taxonomy.js` / `search.js`：10カテゴリ、階層タグ、専用条件、範囲検索。
- `store.js` / `catalog-migration.js`：検証、v3移行、保管・復元、年別集計。
- `app.js` / `index.html` / `style.css`：検索、詳細、段階編集、思い出、バックアップ、レスポンシブUI。
- `tests/`：旧版の回帰テスト、250IDのスナップショット、新検索・移行・履歴保護・年別集計・JSONテスト。
- `scripts/catalogue-summary.mjs`：都県・カテゴリ・特徴・時間の集計。
