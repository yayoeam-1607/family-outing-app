# 検証記録

検証日：2026年10月11日（日本時間）。対象は実在100件のカタログと中断時から継続した移行・検索機能。

## 自動テスト・ビルド

- `npm test`：全テストファイル成功。
- `npm test -- --test-isolation=none`：23テスト成功。検索の境界、旧バックアップ互換、履歴・お気に入り、実際の100件への移行、JSON往復、編集・削除維持、未確認の許可条件、複合検索を検証。
- `npm run build`：Viteの本番ビルド成功。相対アセットパスを維持。
- 100施設の固定ID・施設名の一意性、保存形式、公式確認記録との対応、参照URL、原本ハッシュを点検。カタログの公式施設案内100ページをHTTP取得し、本文・タイトルを確認。エラーページを本番カタログに使用していない。

## Chromiumによる本番ビルドの実画面検証

`dist`を `/family-outing-app/` 配下で配信し、GitHub Pagesと同じサブディレクトリ構成で確認。

- 新規ブラウザ・GitHub Pages形式のサブディレクトリ：100件、公式リンク100件、390px幅で横はみ出しなし
- 雨＋公共交通60分＋5,000円＋2時間＋博物館の複合検索と近い順：2施設の結果が一致
- v1から自動移行：実在100＋ユーザー1、架空10を保管、旧お気に入り・訪問参照・ユーザーメモ・移行前JSONを維持
- 保管した旧施設のお気に入り・履歴を画面で閲覧可能
- 実在施設を編集・再読込して未確認のテント/BBQと家族メモを保持、移行前退避JSONを上書きしない
- 実在施設の削除・再読込：削除済みIDを記録し復活しない
- 実際のJSONダウンロードとファイル選択からの復元：データが完全一致
- 旧v1 JSONのファイル読込でも100施設へ移行し旧履歴を保持
- 不正JSONは読み込みを拒否し既存保存データを維持
- 壊れたlocalStorageは自動移行・操作で上書きしない
- 全シナリオでJavaScript例外とアセット取得エラーなし

移動時間は経路API・実走の検証値ではありません。3施設の仮予算、各施設の予約条件や営業の変更は公式案内で再確認する前提です。確認結果は一定時点の情報で、ライブの営業・交通を保証する機能ではありません。
