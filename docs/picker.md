# おまかせで決める

検索欄の下に入口を追加。既存の350件、カテゴリ検索、データ形式とcatalogRevisionは変更していない。抽選結果もlocalStorageに保存しない。

- **今の検索条件から**：`searchResults(state, criteria)`の全結果を母集団にする。画面の30件表示上限に依存しない。候補数と0件の案内を表示する。検索条件が未指定なら全350件の完全ランダム抽選を開始せず、条件選択またはカテゴリ抽選を案内する。
- **カテゴリから**：自由検索・大カテゴリ・中カテゴリ・タグ・カテゴリ専用条件を解除し、移動時間、料金、駐車場、天候、季節、地域、滞在、未訪問、有名のみなどの共通条件で既存検索を実行。候補のあるカテゴリを均等に選び、その中の施設を均等に選ぶ。施設が多いカテゴリの当選確率は増えない。
- **マイリスト**：既存の`collection()`でお気に入り・最新visitが「また行きたい」・未訪問を取得し、IDでunion。通常検索の条件とは独立して対象リストを使う。非表示施設は除外する。重複・空リストを扱う。
- **もう一回**：母集団に異なる施設が2件以上あれば、直前のIDを次の1回から除外する。カテゴリ抽選も除外後の候補でカテゴリを均等に選ぶ。その結果、直前の施設しかないカテゴリはその1回だけ対象外になる。1件しかなければ同じ施設を再抽選できる。

乱数は`crypto.getRandomValues()`を優先。剰余が偏る値は再取得し、APIがない場合だけ`Math.random()`を使用する。選択を先に確定し、約2秒でカテゴリ→施設または施設名のシャッフルを表示。reduced-motionなら即時表示。二重操作を防止し、閉じる・Escで演出タイマーを解除する。

結果は既存カードを再利用し、施設情報と条件一致ポイントを表示。「この場所を見る」は既存の詳細dialogを開く。390pxのスマートフォンでは画面内のシート風dialogとし、下部ナビはモーダルの背景側に置く。

変更ファイル：`picker.js`（母集団・抽選）、`picker-ui.js`（入口・演出）、`app.js`（連携・共通カード）、`result-presentation.js`（キーワード一致理由）、`index.html`、`style.css`、`tests/picker.test.js`、この説明とREADME。
